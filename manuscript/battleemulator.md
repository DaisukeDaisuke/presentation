# battleemulator

## 要約

- dq9のCテーブル乱数は、1人では非常に論理的。
- Cテーブルは途中で勝手に変わったりしない。
- シード値は48bitで52万づつ増える単調増加

それで何ができますか？

# 過去
dq9一人旅RTAは、イシュダルで5敗するほどの難関RTAであり、多くのボスが原因のリセットが発生した
今まで、過去の英雄にかかっても、Cテーブルを乱数調整しようという試みすらなかった
Cテーブルは2024年まで48bitの巨大な壁だと思われていた。
私はこの状況を打開したいと考えた。

# 2024年3月26日の悲劇
ある配信者がdq9一人旅RTAを旧チャートではじめ、イシュダルまで到達したが、イシュダルの7敗した。
これがなければ、バトルエミュレーターはこの世に存在しなかっただろう。
この時点でうっすらCテーブルは乱数調整できるのではないかと考え始めていた。
乱数は本当に論理的なのでしょうか？

# Cテーブル
内部名は「battle」、64bit LCG
シード値は、ゲーム開始時に始動する48bit精度のタイマーから取得された64bit値が、初期シードとして使用される
戦闘中に乱数を再取得したり、入れ替えたりしない
ポケモンより非常に簡単のようです。 ゲーム内タイマーはどうでしょうか？
cテーブル✅

# ゲーム内タイマー
ゲーム内タイマーは、1秒間に8 * 2**16 = 524,288回増加する。
32bitハードウェアタイマーと、16bitソフトウェアタイマーの合わせ技で実現され、上限は48bit(17年)
dq9で一般に知られているすべての乱数テーブルの初期シードジェネレータ
起動時間を調べる目的でも使用される。
ゲーム内タイマー✅

# 2024年10月
イシュダルの試作が完成した。総当たりが14秒かかり、当時は非常みにくい表示だった。

# シード値の逆算
初期シードは1秒間に8回増加するタイマーであるから、
$`524,288 * 秒数`$
にもどついてある程度のシード値を逆算できます！
48bitを総当たりする必要はありません。
シード値と完璧なバトルエミュレーターが手に入りました。 次は何ですか？
範囲の逆算✅
